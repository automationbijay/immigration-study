# Canada Express Entry CRS Point Calculator

## Overview
This directory contains a data extraction script and a standalone web UI for the **Canadian Comprehensive Ranking System (CRS)**. 

Like the FSW 67-point calculator, the objective of this project was to scrape the questionnaire structure and recreate a dynamic, interactive user interface based on the extracted data.

## Project Structure
- **`scrape_crs.py`**: A Python script utilizing Playwright and BeautifulSoup to automate the browser, parse the HTML, and extract the CRS questionnaire form structure.
- **`crs_points.json`**: The raw output file generated by the scraper. It contains the questions (by their HTML name attributes like `q1`, `q2i`) and their available options mapping to alphabet keys (`A`, `B`, `C`, etc.).
- **`index.html`**: The UI of the CRS Calculator built with HTML, CSS, and Vanilla JavaScript. The JSON data is directly embedded inside the `<script>` tag to prevent browser CORS issues when opened locally.

## Data Source
The base questionnaire structure was dynamically scraped from:
- **Source**: `https://www.siaimmigration.com/CRS-calculator`

## Point Calculation Validation (Important)
**Status: Unvalidated / Mocked**

### The Challenge
Unlike the FSW 67-point calculator where the point values were hardcoded into the HTML element values (e.g., `<input value="13">`), the CRS calculator's HTML utilizes abstract alphabetical keys (e.g., `<input value="A">`, `<input value="B">`). 

The actual CRS score computation is highly complex. The IRCC matrix considers multiple interconnected factors (for example, your age points change depending on whether you are applying with a spouse, and skill transferability points change based on your language scores). The original source website handles this calculation using thousands of lines of customized JavaScript math to map `A`, `B`, and `C` to the correct points based on the combination of answers.

### Current Implementation
Because mapping every single letter combination back to the official 1200-point IRCC matrix requires deep domain implementation rather than just web-scraping, the `index.html` file uses a **mock calculation method** for demonstration purposes.

Currently, the `calculatePoints()` function in `index.html` assigns a dummy mathematical value to each letter (e.g., A=10, B=20, C=30) and caps the sum at 1200. **This means the score shown on the screen is NOT an accurate CRS score.**

### Next Steps for Accuracy
To validate and finalize the point calculation method, a developer will need to:
1. Replace the `mockScore` logic in `index.html`.
2. Implement the official IRCC Express Entry CRS grid logic (which involves `Core / human capital factors`, `Spouse factors`, `Skill transferability factors`, and `Additional points`).
3. Map the scraped HTML question names (`q1`, `q3`, etc.) to that logic.
