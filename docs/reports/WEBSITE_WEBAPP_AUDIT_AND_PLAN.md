# Migration Assistant website and web app audit

22 November 2026

The first release should contain exposed credentials, secure CV processing, and stop publishing unverified scores. Then make the public site useful before signup and make the signed-in app explain what each result means and what the user can do next.

## Scope and verification

The review covered the React/Vite routes and shared UI, Australia and Canada calculators, profile and authentication, Supabase migrations and Edge Functions, CV processing, occupation and university data, Vercel and PWA configuration, monitoring, tests, and operational documentation. Findings about deployments, live data, provider retention, and access policies need confirmation in staging or production. This review used repository source and local checks, with no live CV submissions or database writes.

- **Build** passed. Vite reported an 818 kB initial JS chunk (251 kB gzip) and a 362 kB ANZSCO route chunk (106 kB gzip). The service worker precached 42 entries totaling about 1.35 MiB. Sentry release and sourcemap uploads were skipped because the build lacked an auth token.
- **Lint** passed with 28 warnings, including a CRS effect dependency warning.
- **Browser tests** passed 3/3 in local Chromium after installing the matching Playwright browser. The suite covers landing, lazy login navigation, and one anonymous profile redirect. Signed-in flows and mobile visual behavior still need validation.
- The [August UI audit](UIUX_AUDIT.md) is historical. Current source already includes route splitting, a 404, safe-area viewport settings, keyboard-aware dialogs, comboboxes, reduced-motion CSS, and CV intent handling through signup and login. Preserve these behaviors.

## Implementation roadmap

| Order | Work and suggested owner | Acceptance criteria |
|---|---|---|
| 1 · Containment | **Operations and backend.** Rotate sensitive credentials, inspect access logs, move secrets to managed storage, replace the tracked copy with sanitized examples, and add secret scanning. Check repository history and review tracked CV fixtures and extracted outputs for personal data. Restrict CV workers to verified internal callers and bucket-owned records. **Frontend.** Remove mock CRS results from calculators and Home until old values are handled. | Old sensitive credentials revoked and replaced. Worker authorization covered by staging tests. Raw CV content and processing URLs absent from logs. No mock CRS score is shown, including from previously saved rows. |
| 2 · Scoring and persistence | **Product and frontend with backend support.** Create versioned rules sourced to official program pages. Show points, preconditions, missing inputs and conditional nomination separately. Recalculate old CRS rows only where inputs are sufficient. Use checked, atomic writes where records must move together. Keep edits visible on failure and report success after committed writes. | Fixtures cover Australia 189/190/491, 485 boundaries and exceptions, FSW below/at threshold with and without minimum requirements, and current CRS scoring cases. Reload preserves committed data. Failed requests and simultaneous saves leave consistent state. |
| 3 · Profile and CV reliability | **Backend and frontend.** Confirm one production CV processing path. Make job state durable and show upload, processing, review, applied and retry states. Show extracted values for review before replacing manually entered information. Verify processor retention and make deletion retryable and verifiable across storage and the database. Add staging checks for account recovery, confirmation, and post-login return paths. | With synthetic CVs, upload, replacement, partial failure, timeout, retry and deletion reach accurate terminal states. Two test accounts verify data isolation. A profile section failure keeps other sections usable. |
| 4 · Website and app journeys | **Design, content and frontend.** Give the landing page country-specific entry points and a primary guest “Calculate points” action. Explain what each calculator does, then offer save or CV import after results. Put a country-specific next step on Home. Group Discover around programs, calculators and lookup tools. Add result explainers, data source dates, privacy and CV processing information, and per-route metadata for public pages. | Users can get to an Australia estimate or Canadian tool from the landing page, preserve intent through authentication, and resume from Home. Core flows work at 360 px and with keyboard navigation. Focus, heading order, errors and async announcements pass manual review. Public routes have distinct titles and share previews. |
| 5 · Performance and operations | **Frontend and data/ops.** Measure guest and authenticated startup separately. Keep heavy chart code out of the initial request until needed, review loading of telemetry and fonts, and reduce eager precaching of rarely used assets where measurements support it. Repair PWA icons and test updates and offline behavior without caching private responses. Publish validated, versioned occupation and university snapshots through staging and document blank-environment setup. Add CI for build, lint, scoring, route smoke and staging integration checks. | Track JS transfer and Core Web Vitals before and after the change. Use p75 LCP ≤2.5 s, INP ≤200 ms and CLS ≤0.1 as initial targets where field data is available. Fresh staging can be built from the repo. Data refreshes have source dates, row-count checks, and rollback. CI exercises failed saves, CV flows, route guards, and mobile journeys. |

Track guest calculation completion, result-to-profile conversion, successful CV imports, and write failure rate. Use aggregate events with no CV text, profile values, or exact scores. Establish the baseline before setting conversion targets.
